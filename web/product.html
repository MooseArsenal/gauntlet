How an exercise runs

  1. Model the system under test. Stamp a library environment or import your CMDB, EDR, SIEM or attack-surface export. Assets, controls with efficacy and latency, detections, deception, crown jewels, per-cell visibility.
  2. Build the exercise. Emulate a real ATT&CK group or a designed adversary through an attack-type template, import a CTEP pack, or author a branching scenario in the visual editor.
  3. Run the room. Pre-brief and projector views for the room; join codes for large groups; the facilitator drives from the console by keyboard. Blue, red and observer cells each see only their side.
  4. Adjudicate. Each adversary move is ruled deterministically against the environment. The purple-team loop shows the red cell instantly whether it was caught.
  5. Hotwash and record. Rate every objective before anyone leaves; log improvement items; issue the certificate. Four reports, compliance crosswalks and a Navigator layer come from the same signed timeline.
